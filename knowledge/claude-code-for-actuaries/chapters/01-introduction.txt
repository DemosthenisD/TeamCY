 CHAPTER 1

 Introduction

 1.1 Why This Guide Exists
 Day to day, a large part of actuarial work is technical execution: building models in Python or R,
 reconciling portfolio extracts, maintaining complex Excel workbooks, debugging legacy VBA, and testing
 developments against functional specifications.

 Claude Code turns these tasks into simple instructions. You describe what you want in plain English, and
 Claude Code builds it, runs it, reads its own errors and corrects itself until the result is right.

 This guide is organized by practice area and by team. Whether you are an ALM actuary, an auto pricing
 actuary, a modeler, a reserving actuary or a reinsurance specialist, you will find use cases directly
 applicable to your day-to-day work, with prompts ready to copy and paste.


 1.2 What This Guide Is and What This Guide Is Not
 This guide focuses on Claude Code as a practical tool to support actuarial model development. It
 demonstrates how actuaries can use Claude Code to translate business and modeling requirements into
 working code and accelerate portions of the development process.

 This guide is not a guide to model risk management, actuarial governance, or regulatory compliance.
 Actuaries using Claude Code should continue to operate within established professional, regulatory, and
 organizational frameworks. Relevant guidance includes the International Actuarial Association (IAA)
 standards, particularly ISAP 1A – Governance of Models and ISAP 1 – General Actuarial Practice. In the
 United States, ASOP 56 – Modeling provides important guidance regarding the development, use,
 validation, and governance of models. Regulatory requirements may also apply, including VM-30, VM-G,
 SR 26-2, OSFI E-23, the NAIC AI Model Bulletin, Colorado SB21-169, the AMF Model Risk Management
 Guideline, DFS Circular Letter 2025-7, and any internal governance standards established by an
 organization. Additional guidance may be available from actuarial organizations such as the SOA, CAS,
 AAA, CIA, and other professional bodies.

 This guide is also not a guide to software engineering best practices. Topics such as coding standards,
 code optimization, software architecture, testing strategies, cybersecurity, version control, and long-term
 maintainability are largely outside its scope. While these considerations remain important, they have been
 extensively documented elsewhere.

 Similarly, this guide does not attempt to address many of the core elements of actuarial modeling,
 including business problem formulation, model architecture, assumption development, validation
 frameworks, controls, documentation requirements, change management, or the exercise of professional
 judgment. These remain essential components of the model lifecycle and should be addressed through
 appropriate governance processes.

 than comprehensiveness or implementation of a company/country specific interpretation. The guide

 1.3 How to Read This Guide
 Every use case follows the same structure: the business context, a description of what Claude Code will
 design, a detailed ready-to-use prompt, and the expected inputs and outputs. The prompts are
 deliberately exhaustive: copied as-is, they should produce a usable result.


   Tip: The prompts in this guide are starting points. The more context you add about your own environment
   (file names, conventions, data structures), the more precise the result will be on the first iteration.

 A word on data. The prompts are written against data your company already holds, so they name inputs
 (a portfolio extract, a zero-coupon curve, a loss triangle) without printing their layout. Each use case's
 “Expected inputs” list tells you what the prompt presumes; when the business context is not enough to
 see what a file or a parameter represents, the companion packs close the gap: each pack's CLAUDE.md
 carries the full data dictionary — every file, every column, every parameter, and how they map to the
 prompt's functions. For your own data, do the same: describe the layout in your CLAUDE.md (the chapter
 12 template has a section for it), and the prompt will land on the first try.


 1.4 Companion Project Folders
 Several use cases in this guide come with a downloadable companion project folder: the CLAUDE.md,
 the ready-to-paste prompts and the dataset. Look for the green “Companion resources” boxes. Download
 the folder, open it in Claude Code, paste the prompt, and replicate the use case end to end on your own
 machine. Some datasets keep their original file and column names (occasionally in French, as noted in
 each pack): leave them unchanged so the prompts run as-is.
