 CHAPTER 10

 Security, Confidentiality and AI
 Governance
 Insurance data is among the most sensitive there is: personal data, health data, financial data. Using an
 AI tool in this context demands clear rules. This chapter is not optional: it conditions the very possibility of
 using these tools in a regulated professional setting. It also reflects a reality of the US market: regulators
 are actively building expectations for insurers' use of AI.


 The right question, and who answers it
 This guide will not hand you a confidentiality rulebook, because the honest answer is simpler: the
 modalities under which you may use Claude Code on professional data are set by your company, not by a
 book. Before processing anything beyond public or synthetic data, talk to your IT security and compliance
 teams and ask the one question that matters: under which deployment, and on which classes of data, is
 the tool approved here?

 The reason the question deserves a real answer is that most of what an actuary produces — rate filings,
 regulatory reports, valuation memos — is confidential by nature. Keeping all of it away from the tool would
 take away most of the tool's usefulness; the working answer in many companies is a deployment that has
 been locked away from communication with the outside world and validated by IT security, so that
 confidential work can happen inside a controlled perimeter. What that perimeter looks like — enterprise
 plan with contractual no-training guarantees, dedicated environment, scoped accounts — is exactly what
 your IT department will tell you.

 On an individual plan, the account-level setting shown in chapter 3 (turning off “Help improve our AI
 models”) controls whether your conversations and coding sessions may be used for model training.
 Review it before your first session; in a corporate setting it complements, and never replaces, your
 company's own controls.

 Whatever the deployment, three reflexes cost nothing and always apply:

     • Secrets: never paste secrets (passwords, API keys, connection strings) into a prompt. Use
     environment variables.
     • Review before execution: have generated code reviewed before running it on real data, especially
     if it writes, moves or deletes files.
     • Logging: log the actions of tools and agents so you can audit what was done.

 What to remember
 AI changes how you work, not your responsibility framework. An actuary using Claude Code is held to the
 same standards of rigor, documentation and compliance as if everything had been written by hand. Good
 practice treats AI-produced code and analyses exactly like a junior colleague's: useful, fast, but
 systematically reviewed and validated before anything is committed.


   Golden rule: Use AI to automate execution, not accountability. AI accelerates the work; it does not dilute
   responsibility. The actuary remains accountable for the models, the results and their compliance.
