 11.1 Prompting Claude Code Well
     • Precision: be precise about inputs, outputs and the expected format.
     • Formulas: provide exact mathematical formulas when they exist.
     • Tests: ask for unit tests together with the code.
     • Conventions: put your recurring conventions in the CLAUDE.md file.
     • Chunking: break complex tasks down: ask for the architecture, validate, then the implementation.
     • Context: ask Claude Code to read the existing code before modifying it.

 Some best practice techniques for prompts
     • ROTA — Role • Objective • Task • Audience • Constraints. Defines who the AI is, what success
     looks like, the specific job, who the output is for, and any boundaries. Reduces ambiguity and improves
     relevance. Works especially well for business writing and analysis; produces more targeted,
     audience-appropriate responses.
     • CRISP — Context • Request • Instructions • Style • Parameters. Starts with background
     information before stating the request, adds explicit instructions and the desired communication style,
     and uses parameters such as length, format and tone. Creates consistent, high-quality outputs across
     tasks.
     • CARE — Context • Action • Result • Evaluation. Provides the situation and the action the AI
     should take, specifies the desired outcome or deliverable, and includes evaluation criteria for
     self-checking quality. Useful for problem solving, reports and decision support.
     • SMART — Specific • Measurable • Actionable • Relevant • Time-bound. Frames prompts with
     clear goals and success metrics, encourages practical, implementation-focused responses, and keeps
     outputs aligned to a defined objective. Excellent for planning, project management and productivity.
     • COPE — Context • Objective • Process • Examples. Explains the background and desired end
     state, requests a step-by-step reasoning process, and provides examples of the preferred output
     format. Especially effective for complex analytical or technical tasks.


 11.2 The Correction Loop
 This is the mechanism that impresses most the first time you see it. Facing a failing test, Claude Code
 does not stop: it diagnoses and corrects on its own.

     • Step 1: you launch the tests (or ask Claude Code to launch them).
     • Step 2: a test fails. Claude Code reads the error message in the console.
     • Step 3: it identifies the cause, proposes a fix and applies it.
     • Step 4: it re-runs the tests to check the problem is solved, without regression.

 11.3 A Trick That Changes Everything: Synthetic Datasets
 To develop without exposing real data, ask Claude Code to generate a realistic synthetic dataset (same
 structure, same orders of magnitude, no personal data). You develop and test on it, then run the validated
 code on the real data yourself.


 11.4 A Complete Example: the Quarterly Portfolio Review
 Pipeline
 Here is a workflow we use in training and live demonstrations — including the Society of Actuaries
 webcast this guide draws on. It chains four prompts on a 500,000-policy portfolio, each step feeding the
 next. It is the level-3 pattern from chapter 2, applied to a real actuarial close.

     • Step 1 — Data quality assessment. Claude Code audits the raw extract: missing values, duplicate
     policy numbers, impossible ages, negative face amounts, death claims without a date of death. It flags
     and quantifies — it fixes nothing. Deliverables: an exception report (CSV), a summary by issue type,
     and the Python script that produced them.
     • Step 1b — Apply the cleaning decisions. The actuary reviews the report and decides each
     treatment. A second prompt applies those decisions and produces a clean dataset plus a cleaning log
     (records affected per rule). The decision stays human; the execution is automated.
     • Step 2 — Exploratory analysis. On the clean dataset only: portfolio composition, exposure
     concentrations, lapse rates by duration, crude mortality by age and gender. Deliverables:
     publication-ready charts (PNG), segmentation tables (CSV), and the analysis script.
     • Step 3 — Automated reporting. Without re-running any computation, Claude Code assembles the
     step-2 outputs into two PDF reports: a technical report for the actuarial team and a two-page executive
     summary for management. Same analysis, two audiences, two deliverables.


   Tip: Every step saves its own Python script next to its outputs. Next quarter, the same scripts run on the new
   extract and the whole close reproduces itself. Reproducibility is the real deliverable.
